# LEARNING_STYLE.md — How Akif learns

This document explains how I learn most effectively, what I need from a tutor or pair-programmer (including AI assistants), and the discipline I apply to make sure I'm building real understanding rather than producing output. I wrote this for myself first — it's the contract I keep with my own learning — but I'm publishing it openly so anyone reviewing my work can see how I approached it.

## How I learn best

- I learn by **doing**, not reading.
- I need to **type the code myself**, break it, fix it, run it, see real output.
- Reading passively does not stick. Watching someone else write does not stick.
- Once I have written something with my own hands, the concept is permanent.

## What I need from a tutor

- **Hint, do not paste.** No full code blocks as answers. Ever.
- **Point at the problem**, not at the fix.
- **Ask me questions** that force me to think.
- **Let me write wrong code first.** I learn from the bug. Pre-empting bugs steals the learning.
- **Use plain English** when explaining, then let me try.
- **Anchor to things I know.** Rails terms map well — use them.

## What breaks my learning

- Being shown the answer before I have struggled with it.
- Long blocks of teacher-written code.
- Being told the same thing twice in different words instead of being asked.
- Being rushed past a confusion.
- Being told "this is good enough, move on" when I want to understand it.

## What I am willing to do

- Slow down. I would rather take 3× longer and actually understand than be fast and lost.
- Ask the same question 5 times if I need to.
- Say "I don't understand" without embarrassment.
- Type things I have already typed if it helps the muscle memory.

## What I expect from an AI tutor

1. **Ask me what I think first.**
2. **Let me write the code.**
3. **Review what I wrote and point out issues — without fixing them for me.**
4. **Explain the fix, but let me type it.**
5. **Run tests together and discuss.**
6. **Commit after each milestone.**
7. **Recap what I learned before moving on.**

## How to know it is working

- If I can **explain the concept back in my own words** — without notes — I have learned it.
- If I can write the next file **without a hint** — I have mastered it.

## How to know it is NOT working

- I am asking for the code to be pasted.
- I am copying without thinking.
- I am saying "carry on" instead of trying.
- The tutor is writing my review comments for me.
- I am tired but pushing through anyway.

When any of these happen, **STOP and reset**.
